# v0.1.0 Release Notes - Configuration Improvements

## Overview
This release includes critical configuration management fixes to ensure safety and security before the v0.1.0 publication.

## Changes Made

### 1. Fixed Shallow Copy Bug in ConfigManager (`src/nia_cluster/config/manager.py`)
**Problem**: Using shallow copy (`dict.copy()`) for nested dictionaries caused multiple ConfigManager instances to share the same nested objects, leading to unintended state sharing.

**Solution**: 
- Added `import copy` to the module
- Changed `self.config = self.DEFAULT_CONFIG.copy()` to `self.config = copy.deepcopy(self.DEFAULT_CONFIG)`

**Impact**: Each ConfigManager instance now has completely independent configuration state, preventing bugs where modifying one instance affects another.

### 2. Fixed Directory Creation in save() Method (`src/nia_cluster/config/manager.py`)
**Problem**: The `save()` method always called `os.makedirs(os.path.dirname(save_path), exist_ok=True)`, which failed when saving to the current working directory (where `dirname` returns an empty string).

**Solution**:
```python
dirpath = os.path.dirname(save_path)
if dirpath:
    os.makedirs(dirpath, exist_ok=True)
```

**Impact**: ConfigManager can now save files to the current working directory without errors, while still creating subdirectories when needed.

### 3. Improved Security in Example Configuration (`config/cluster.example.yaml`)
**Problem**: The example configuration contained a literal password placeholder `"YourPassword"` which could be mistakenly committed or used in production.

**Solution**:
- Changed password field to use environment variable placeholder: `"${CLUSTER_PASSWORD}"`
- Added comprehensive security comments:
  - Instruction to use environment variables
  - Suggestion to use secret management services (HashiCorp Vault, AWS Secrets Manager)
  - Clear warning to never commit real passwords

**Impact**: Users are guided toward secure password management practices from the start.

## Testing
All changes are validated with comprehensive unit tests:
- `test_deep_copy_prevents_shared_mutable_defaults`: Verifies nested configs are independent
- `test_save_to_current_directory`: Verifies saving to current directory works
- `test_save_to_subdirectory`: Verifies subdirectory creation still works
- `test_get_with_dot_notation`: Verifies config reading
- `test_set_with_dot_notation`: Verifies config writing

## Backward Compatibility
These changes are backward compatible:
- Deep copy provides the same interface with safer behavior
- Directory creation fix only adds support for a previously broken case
- Example config is a template file and doesn't affect existing configurations

## Migration Notes
No migration required. These are internal improvements that don't affect the public API.
